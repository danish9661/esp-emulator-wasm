# AGENT.md — Multi-Target RISC-V & Peripheral Architecture for `esp-emu`

Comprehensive architectural documentation for the WebAssembly ESP32 RISC-V emulator, supporting **ESP32-C3**, **ESP32-C6**, **ESP32-H2**, and **ESP32-P4** with a decoupled, Wokwi-style peripheral bridge and `rp2040js`-style MCU SDK.

---

## 1. Supported Espressif RISC-V Target Chips

The underlying WebAssembly core (compiled from Espressif's open-source [`esp-emulator`](https://github.com/espressif/esp-emulator) v0.39.0) contains built-in ROMs and hardware models for **4 RISC-V target architectures**:

| Chip Identifier | Architecture | Clock / Cores | Memory / Cache | Wireless & Peripherals | Built-in ROM Signature |
|---|---|---|---|---|---|
| **`esp32c3`** | Single RV32IMC | 160 MHz (1 core) | 400 KB SRAM, 384 KB ROM | Wi-Fi 4, BLE 5, 22 GPIOs, I2C, SPI, ADC, PWM, I2S, TWAI | `ESP-ROM:esp32c3-api1-20210207` |
| **`esp32c6`** | Single RV32IMAC | 160 MHz (1 core) | 512 KB SRAM, 320 KB ROM | Wi-Fi 6, BLE 5, 802.15.4 (Zigbee/Thread), 30 GPIOs | `ESP-ROM:esp32c6-20220919` |
| **`esp32h2`** | Single RV32IMAC | 96 MHz (1 core) | 320 KB SRAM, 128 KB ROM | BLE 5, 802.15.4 (Zigbee/Thread), 19 GPIOs | `ESP-ROM:esp32h2-20221101` |
| **`esp32p4`** | Dual RV32IMAFC | 400 MHz (2 cores) | 768 KB SRAM, FPU (Single/Double), H.264, MIPI CSI/DSI | High-Performance SoC (No wireless) | `ESP-ROM:esp32p4` |

## 2. Universal RV32 Binary Compatibility

All runtime assembly shims ([`shims.mjs`](file:///home/danish1075/Documents/espc3%20wasm/shims.mjs)) are generated by [`spike/gen_spi_shims.py`](file:///home/danish1075/Documents/espc3%20wasm/spike/gen_spi_shims.py) and use **only standard RV32I base integer instructions**:

- Register operations: `addi`, `lui`, `slli`, `srli`, `andi`, `or`
- Memory load/store: `lw`, `sw`, `sb`
- Control flow: `bne`, `beq`, `jalr` (ret)
- UART0 FIFO polling: `0x60000000` (UART0 register base, identical on all 4 chips)

Because RV32I is the common denominator across `RV32IMC`, `RV32IMAC`, and `RV32IMAFC`, **the exact same shim bytecode executes natively on all 4 target chips** without requiring chip-specific recompilation.

## 3. How to Compile Firmware for Each Target

### 3.1 Using `arduino-cli`

Set `export TMPDIR=/tmp/isolated_path` before compiling to avoid PyInstaller collisions in sandbox environments.

```bash
# 1. ESP32-C3
arduino-cli compile --fqbn esp32:esp32:esp32c3 sketch_dir --output-dir build_c3

# 2. ESP32-C6
arduino-cli compile --fqbn esp32:esp32:esp32c6 sketch_dir --output-dir build_c6

# 3. ESP32-H2
arduino-cli compile --fqbn esp32:esp32:esp32h2 sketch_dir --output-dir build_h2

# 4. ESP32-P4
arduino-cli compile --fqbn esp32:esp32:esp32p4 sketch_dir --output-dir build_p4
```

### 3.2 Using Pure ESP-IDF (`idf.py`)

```bash
# Set target chip and build
idf.py set-target esp32c3   # or esp32c6 | esp32h2 | esp32p4
idf.py build
```

The build produces:
- Flash image: `project.merged.bin` (or bootloader + partition table + app binary merged at offset 0x0)
- Symbol ELF: `project.elf` (used by `elf.mjs` for load-time symbol discovery and binary patching)

## 4. Multi-Target Initialization via `ESP32C3` / `core/` SDK

The `ESP32C3` MCU engine class accepts any of the 4 target chip identifiers:

```javascript
import { readFileSync } from 'node:fs';
import { ESP32C3 } from './index.mjs';

// Instantiate for any target chip: 'esp32c3' | 'esp32c6' | 'esp32h2' | 'esp32p4'
const mcu = await ESP32C3.create({
    chip: 'esp32c6',        // or 'esp32h2', 'esp32p4', 'esp32c3'
    bootFromRom: true,
});

// Load target firmware and apply automatic ELF symbol shims
const flash = new Uint8Array(readFileSync('samples/c6_firmware.merged.bin'));
const elf = new Uint8Array(readFileSync('samples/c6_firmware.elf'));
const { patched } = await mcu.loadFirmware(flash, elf);

console.log(`Patched ${patched.length} driver shims on ${mcu.chip}`);

// Step execution
while (mcu.running) {
    const text = mcu.step(50000);
    if (text) process.stdout.write(text);
}
```

## 5. Automated Multi-Chip Verification Pattern

To add an automated test suite for a new chip target (e.g. `spike/21-verify-c6.mjs` or `spike/22-verify-h2.mjs`):

```javascript
import { readFileSync } from 'node:fs';
import { ESP32C3 } from '../index.mjs';

async function testTargetChip(chipName, binPath, elfPath) {
    console.log(`Testing Target: ${chipName}...`);
    const mcu = await ESP32C3.create({ chip: chipName, bootFromRom: true });
    await mcu.loadFirmware(readFileSync(binPath), readFileSync(elfPath));

    let consoleOutput = '';
    mcu.uart0.onData(chunk => { consoleOutput += chunk; });

    for (let i = 0; i < 1000; i++) {
        mcu.step(50000);
        if (consoleOutput.includes('app_main') || consoleOutput.includes('setup()')) break;
    }

    console.log(`✓ Boot verified on ${chipName}! Cycles: ${mcu.cycles}, PC: 0x${mcu.pc.toString(16)}`);
}
```

## 6. Capability & Protocol Summary (All Targets)

| Peripheral / Protocol | Status | Intercepted Driver Symbols | Protocol Mechanism |
|---|:---:|---|---|
| **UART0 Console** | ✅ | Serial TX/RX FIFO | Native WASM FIFO + XTerm.js |
| **GPIO (Pins 0..21+)** | ✅ | Direct hardware registers | Dynamic WASM linear memory auto-calibration |
| **I2C Master** | ✅ | `i2cWrite`, `i2cRead`, `i2cWriteReadNonStop` | APC escape frames (`\x1b_W`, `\x1b_R`) over UART0 |
| **SPI Master** | ✅ | `spiTransferByte`, `spiWriteByteNL`, `spiTransferBytesNL`, etc. | Chunked APC escape frames (`\x1b_S`, `\x1b_SX`) |
| **NeoPixel (WS2812 RMT)**| ✅ | `espShow`, `neopixelWrite` | APC RGB frames (`\x1b_N`) |
| **ADC (12-bit SAR)** | ✅ | `analogRead`, `analogReadMilliVolts` | APC sampling frames (`\x1b_A`, `\x1b_V`) |
| **PWM / LEDC** | ✅ | `analogWrite`, `ledcWrite` | APC duty update frames (`\x1b_P`) |
| **I2S Digital Audio** | ✅ | `i2s_write`, `i2s_driver_install` | APC PCM streaming frames (`\x1b_I`) |
| **TWAI / CAN Bus** | ✅ | `twai_transmit_v2`, `twai_receive_v2` | APC CAN frames (`\x1b_C`, `\x1b_CR`) |
| **Storage (SD Card)** | ✅ | SPI block sector engine | Virtual FAT16/FAT32 CCITT CRC16 sector streamer |
